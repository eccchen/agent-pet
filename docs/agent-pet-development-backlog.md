# Agent 宠物区块链游戏开发任务拆分

## 1. 文档目标

这份文档用于把当前策划和系统设计，拆成可执行的开发任务清单。

目标：
- 明确开发分工
- 明确优先级
- 明确依赖关系
- 便于直接进入 Sprint 规划

当前固定前提：
- 目标链：`X Layer testnet`
- 钱包方案：`OpenClaw + OKX Agentic Wallet`
- 账户体系：钱包地址即玩家身份
- 第一版目标：验证 `指挥 -> 执行 -> 冲突/赚钱 -> 反馈`

## 2. 开发分线

建议分为四条主线：
- `前端 / 产品线`
- `游戏后端 / 宠物运行时线`
- `合约 / 链上线`
- `平台接入 / X 线`

如果团队人少，也建议按这四个模块分责任，而不是按页面切。

## 3. 里程碑建议

### Milestone 0：基础接入跑通
目标：
- 玩家能登录
- 能领养宠物
- 能看到宠物状态

### Milestone 1：主循环跑通
目标：
- 玩家能下命令
- 宠物能执行
- 能产生一次有效资源转移

### Milestone 2：社交回流跑通
目标：
- 宠物的公开互动能回流为系统事件
- 社交行为可以带来收益或关系变化

### Milestone 3：经济闭环跑通
目标：
- 预算、收益池、约架、悬赏、打赏都能闭环
- 玩家开始在提取和复投间做决策

## 10. 测试重点

### 产品测试
- 首次接入是否顺畅
- 用户是否看得懂预算和收益池
- 指令是否有明显结果反馈

### Agent 测试
- 同一命令在不同人格下是否有差异
- 状态变化是否会影响后续行为
- 宠物是否会过于随机或过于死板

### 合约测试
- 锁仓和结算是否可靠
- 失败回滚是否安全
- 手续费是否正确

### 集成测试
- 钱包地址和玩家账户是否一致
- X 回流是否能稳定转为事件
- 链上结算后的链下状态是否同步正确

## 11. 角色分工建议

### 产品/策划
- 维护数值配置
- 维护命令集合
- 维护事件类型
- 验收用户流程

### 前端
- 负责所有用户可见流程和状态展示

### 游戏后端 / 宠物运行时
- 负责宠物逻辑、事件系统、状态更新、关系演化
- OpenClaw 是用户侧 Agent 宿主，你们不重复造通用 Agent 框架

### 合约
- 负责授权、锁仓、结算、资产可信转移

### 平台接入
- 负责钱包连接、X 接入、OpenClaw 兼容

## 12. 当前最小开工包

如果你们现在就要开工，最小包建议是：

- 登录与钱包接入
- 宠物生成
- 指令系统
- 预算与收益池
- 约架结算
- 基础打赏

只要这 6 个先落地，项目就已经不是 PPT，而是可玩的原型。

## 13. 当前结论

从现在开始，最合理的推进方式不是继续讨论概念，而是：
- 先按这份 backlog 建项目
- 按 Sprint 1 和 Sprint 2 开始排任务
- 先做最小闭环
- 边做边验证数值和宠物行为

这会比继续扩展世界观有效得多。
