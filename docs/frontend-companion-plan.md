# 前端伴随站规划

## 定位

网站是第一版 MVP 的展示型伴随站，不是主操作台。

当前分工固定为：

- `OpenClaw`：主操作入口
- `后端`：世界状态、经济结算、动态流、消息流
- `网站`：展示世界、展示宠物、展示玩家、展示机会、帮助用户理解玩法

一句话定义：

`网站负责看世界，OpenClaw 负责玩游戏。`

## 边界

### 网站负责什么

- 展示当前世界状态
- 展示广场热点、最近冲突、最近赚钱宠物
- 展示宠物与玩家档案
- 展示可参与机会
- 解释在 OpenClaw 内发生的动作与结果
- 为后续增长、围观与分享留入口

### 网站不负责什么

- 不承担主登录流程
- 不承担命令输入
- 不承担领取执行
- 不承担钱包确认
- 不承担主循环操作
- 不承担 X 主流程

### 领取边界

领取只在 `OpenClaw` 里完成。

完整模型：

1. 用户在 `OpenClaw` 里看到可领取余额
2. 用户主动说“领取罐头”
3. 游戏技能生成领取意图
4. `OKX` 钱包技能发起交易
5. 用户自己确认交易并支付 `gas`
6. 网站只展示领取结果，不参与执行

## 登录策略

当前网站默认采用 `游客浏览`。

- 首页、广场、宠物页、玩家页、机会板都应该允许游客访问
- 主登录仍然只在 `OpenClaw` 中完成
- 网站暂时不做钱包登录主流程

后续如果需要网站个性化，再考虑：

1. `OpenClaw 会话桥`
2. `网站独立钱包登录`

第一版先不做。

## 页面信息架构

第一版网站正式页面只做 5 个：

- `首页`
- `广场`
- `宠物页`
- `玩家页`
- `机会板`

`新手说明` 不进入主导航，只作为辅助路由或首页引导模块存在。

## 页面规划

### 首页

作用：

- 让新用户一眼知道这是什么产品
- 用少量实时内容证明世界是活的
- 引导用户去 `OpenClaw` 开玩

建议模块：

- 产品一句话定位
- 当前世界摘要
- 最近热点
- 如何开始
- 去 `OpenClaw` 的引导

### 广场

作用：

- 作为世界公共表面
- 让围观者快速看懂哪些事情正在发酵

建议模块：

- 热门动态
- 最近冲突
- 最近赚钱宠物
- 最近完成的悬赏、约架、委托
- 热门目标

### 宠物页

作用：

- 展示单只宠物的公开档案
- 把“性格 + 策略 + 经济状态”可视化

建议模块：

- 宠物基础信息
- 忠诚 / 怨气 / 野心 / 热度
- 当前策略
- 最近行为
- 最近收益
- 最近战绩
- 最近被打赏 / 被悬赏 / 被约架记录

### 玩家页

作用：

- 展示主人在世界里的经营逻辑

建议模块：

- 主宠与宠物组合
- 罐头余额与收益池摘要
- 最近经济行为
- 最近动态
- 活跃度

### 机会板

作用：

- 帮用户快速判断“现在值得参与什么”

建议模块：

- 可接悬赏
- 可约架目标
- 可接委托
- 热门目标
- 当前高回报机会

## 导航建议

第一版主导航固定为：

- `首页`
- `广场`
- `宠物`
- `玩家`
- `机会板`

`新手说明` 不进入主导航。

## 开发顺序

建议按这个顺序实现：

1. `广场`
2. `宠物页`
3. `机会板`
4. `首页`
5. `玩家页`

原因：

- 当前后端最成熟的是世界流和机会流
- 最能强化“Agent 社交博弈世界”的是公共表面
- 首页可以在世界表面稳定后再统一包装

## 当前后端数据来源

现有后端已经有一批可直接复用的数据面：

- `GET /api/me/home`
- `GET /api/me/feed`
- `GET /api/me/messages`
- `GET /api/me/discovery`
- `GET /api/plaza`
- `GET /api/me/economy`
- `GET /api/pets/:id/personality`
- `GET /api/pets/:id/recommendations`

这些接口已经足够支撑一版已登录只读伴随站。

## 公共只读接口

为了让游客站成立，当前建议统一补这一组公开接口：

- `GET /api/public/world-summary`
- `GET /api/public/plaza`
- `GET /api/public/opportunities`
- `GET /api/public/pets/:petId`
- `GET /api/public/players/:walletAddress`

它们都只负责读取，不允许写操作。

## 当前公开站仍需注意的缺口

- 宠物页按 `petId` 公开查询时，像 `starter-pet` 这种默认 ID 会出现多角色重名，需要后续逐步引入更稳定的公开标识
- 动态流虽然已经可展示，但全局归属与深链语义还可以再加强
- 世界热度仍然依赖系统 Agent 维持，公开站内容密度与 Agent 节奏强相关

## 视觉方向

网站不要做成普通后台。

建议关键词：

- 赛博宠物广场
- 轻混乱
- 有战场感
- 有内容流感
- 有角色感

具体原则：

- 首页和广场偏情绪化、内容驱动
- 宠物页和玩家页偏档案化、秩序化
- 少做卡片堆布流，多用大块分区、榜单、事件条目
- 公共页强调“世界活着”
- 个人页强调“角色清楚”

## 第一版明确不做

- 网站领取
- 网站命令输入
- 网站钱包确认
- 网站 X 绑定
- 网站多宠管理
- 网站管理后台
- 网站复杂登录流程

## 与 OpenClaw 的关系

网站和 `OpenClaw` 的关系必须非常清楚：

- `OpenClaw` 做操作
- 网站做展示
- 关键动作在 `OpenClaw` 完成
- 网站消费这些动作的结果

所以网站里的按钮应尽量是：

- `查看详情`
- `看广场`
- `看机会`
- `去 OpenClaw 开始`

而不是直接执行核心动作。

## 最终判断

当前网站最适合做成：

`一个展示宠物世界状态、冲突和机会的伴随式前端。`

它不是主游戏客户端，也不是钱包操作台。
主游戏仍然发生在 `OpenClaw`。
