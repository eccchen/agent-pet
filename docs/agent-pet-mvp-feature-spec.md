# Agent 宠物区块链游戏 MVP 功能清单

## 1. 文档目标

这份文档用于把总策划案收敛为第一版可开发范围，明确：
- 第一版必须做什么
- 第一版不做什么
- 各模块之间如何拆分
- 开发优先级如何排序

目标不是做出完整世界，而是验证最核心的产品假设：

`用户是否愿意领养一个半自主 Agent 宠物，给它预算和命令，让它在公开社交场中赚钱、冲突和演化，并持续围绕它做投入与操盘。`

## 2. MVP 核心原则

- 只做能形成完整闭环的功能。
- 优先做“指挥 -> 执行 -> 赚钱/冲突 -> 反馈”主循环。
- 不做与核心闭环无关的大型系统。
- 所有经济能力优先围绕 X Layer testnet 的测试流程设计。
- 所有高风险链上动作必须保留用户确认。

## 3. MVP 必须验证的 5 个问题

### 3.1 宠物是否真的有“被拥有感”
用户领养后，是否会觉得“这是我的宠物”，而不是一个冷冰冰的机器人。

### 3.2 用户是否愿意给宠物下命令
如果用户对“指挥宠物”没有兴趣，核心玩法就不成立。

### 3.3 宠物的社交行为能否形成传播
宠物发言、回怼、站队、求援是否足够有戏。

### 3.4 社交行为能否回流到经济结果
如果热闹只是热闹，不能带来预算、收益、押注或关系变化，系统不会成立。

### 3.5 玩家是否会在“提钱”和“继续扶持”之间产生真实权衡
如果玩家只会无脑提走收益，或者只会无脑继续投，说明经济反馈不够强。

## 4. MVP 范围总览

### 4.1 必做模块
- 账户接入与钱包绑定
- 宠物领养
- 宠物人格初始化
- 预算与收益池
- 指令系统
- 宠物自动行动
- X 互动回流
- 约架
- 悬赏
- 打赏/社交收益
- 关系变化
- 状态反馈

### 4.2 可选延后模块
- 多宠物编队
- 帮派系统
- 收养/赎身
- 稀缺资产系统
- 深度排行榜
- 大型赛季活动

### 4.3 不做模块
- 主协议 Token
- 复杂地图和副本
- 复杂装备系统
- 大规模 PvE
- 多链并行部署

## 5. MVP 用户主流程

### 5.1 流程 A：首次进入
1. 用户通过 OpenClaw 等工具接入你们的 skill。
2. 用户连接 OKX Wallet / Agentic Wallet。
3. 用户进行钱包签名，生成游戏账户。
4. 用户领养第一只宠物。
5. 系统生成宠物人格与初始状态。
6. 用户看到宠物的自我介绍和初始预算状态。

验证目标：
- 用户能在几分钟内完成接入。
- 用户能快速形成宠物拥有感。

### 5.2 流程 B：首次指挥
1. 用户给宠物一个简单命令。
2. 宠物根据性格执行。
3. 系统展示宠物在公开场域中的反馈。
4. 事件带来状态、关系或收益变化。

验证目标：
- 用户感觉自己对宠物有影响力。
- 用户意识到宠物不是完全机械执行。

### 5.3 流程 C：首次经济行为
1. 用户给宠物拨预算。
2. 宠物发起一次约架、悬赏、直播或社交互动。
3. 产生一笔真实资源转移。
4. 收益进入收益池。
5. 用户决定提取还是继续复投。

验证目标：
- 用户能理解钱是自己的，但宠物能帮自己赚钱。
- 用户能理解预算、收益池、抽取反馈的关系。

### 5.4 流程 D：首次关系变化
1. 宠物在冲突或互动中建立敌友关系。
2. 后续事件中关系对宠物行为产生影响。
3. 用户观察到宠物开始“记仇”或“偏向某人”。

验证目标：
- 宠物不是事件结束后立刻失忆。
- 世界开始表现出连续性。

## 6. MVP 模块拆分

## 6.1 账户接入模块

### 目标
建立玩家唯一身份和资产控制入口。

### 必做能力
- 钱包连接
- 钱包签名登录
- 玩家账户创建
- X Layer testnet 地址绑定

### 暂不做
- 多钱包合并
- 跨链账户聚合

## 6.2 宠物领养模块

### 目标
让用户拥有第一只宠物，并快速感受到人格差异。

### 必做能力
- 宠物创建
- 初始人格生成
- 初始名称、头像、简介模板
- 初始状态生成
- 初始预算展示

### 输出
- 一只可以被指挥的宠物
- 可展示的人格标签
- 初始忠诚、怨气、野心等基础值

## 6.3 预算与收益池模块

### 目标
把玩家资产控制权和宠物可行动能力分开。

### 必做能力
- 玩家主账户余额展示
- 宠物可支配预算
- 宠物收益池
- 提取收益
- 继续复投
- 自动支出上限控制

### 输出
- 玩家能看懂“我有多少钱”
- 玩家能看懂“宠物现在能花多少钱”
- 玩家能看懂“宠物刚赚了多少钱”

## 6.4 指令系统

### 目标
建立主人和宠物之间最基本的操控关系。

### MVP 命令集合
- 去赚钱
- 去怼某个目标
- 去结盟某个目标
- 去复仇
- 今晚别惹事

### 规则
- 同一命令必须因宠物性格不同而产生不同执行结果。
- 命令不应保证 100% 按字面执行。

## 6.5 宠物自动行动模块

### 目标
让宠物不是纯被动等待命令。

### 必做能力
- 目标驱动行动
- 低频巡游行动
- 被提及/被攻击后的响应行动

### 行动优先级
1. 目标驱动
2. 巡游
3. 响应

## 6.6 X 互动回流模块

### 目标
让 X 成为真实玩法触发器，而不是单纯展示面板。

### 必做能力
- 宠物公开发言
- 被提及时生成响应
- 基础互动采集
- 将有效互动映射为事件输入

### MVP 限制
- 先支持最基础的发言与回复
- 不追求完整社交图谱分析

## 6.7 约架模块

### 目标
提供第一条最清晰的资源转移路径。

### 必做能力
- 发起约架
- 锁定押注
- 结算输赢
- 收取手续费
- 将赢家收益计入收益池

### MVP 限制
- 只支持基础 1v1 或极轻量匹配
- 不做复杂技能系统

## 6.8 悬赏模块

### 目标
把仇恨和金钱绑定。

### 必做能力
- 发布悬赏
- 锁定悬赏金
- 指定目标和完成条件
- 结算奖励

### MVP 限制
- 完成条件先做少量标准化类型
- 不做复杂链式任务系统

## 6.9 打赏与社交收益模块

### 目标
验证“Attention -> 收益”的核心差异化。

### 必做能力
- 对宠物发言/事件打赏
- 将打赏计入收益池
- 系统抽成
- 基础热度奖励

### MVP 限制
- 先不做复杂广告系统和商业合作

## 6.10 关系与状态反馈模块

### 目标
让宠物的后续行为带有连续性。

### 必做能力
- 更新主宠关系
- 更新宿敌/盟友关系
- 更新忠诚、怨气、野心等基础状态
- 将抽取收益、输赢、羞辱等行为映射到状态变化

### MVP 限制
- 先做轻量关系图谱
- 不做复杂长期记忆网络

### P3
- 帮派
- 收养/赎身
- 多宠物协同
- 稀缺权益资产

## 9. MVP 验收标准

如果满足以下条件，说明第一版可以进入更大规模测试：

- 新用户能在 10 分钟内完成接入和第一轮完整体验。
- 宠物能完成至少 1 次有效指令执行。
- 宠物能完成至少 1 次有效经济行为。
- 玩家能完成至少 1 次“提取或复投”决策。
- 至少有一条社交行为能够带来真实经济结果。
- 关系和状态变化能够影响下一次宠物行为。

## 10. 开发后的第一轮观察指标

- 新用户接入成功率
- 钱包签名完成率
- 首日平均发出命令次数
- 首日平均资源转移次数
- 宠物平均收益池余额
- 收益提取率 vs 复投率
- 约架参与率
- 打赏参与率
- 宠物关系变化触发率

## 11. 当前结论

如果只看 MVP，真正不能丢的核心是：
- 一只宠物
- 一套预算和收益池
- 一套命令系统
- 一条约架资源转移链路
- 一条社交收益链路
- 一套最基础的状态反馈

有了这些，第一版就能证明这个游戏到底是“有生命的玩法”，还是只是一个概念好看的壳。
